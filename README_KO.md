# Grim DPS Lab 3.0 BETA — 장비·스킬·별자리 자동 연결

**배포 상태: 자동 계산 베타. 전체 게임 동작 재현, 실제 전체 DB 첫 다운로드, 네이티브 Windows 실행 검증은 완료되지 않았습니다.**

v2에서 수동이었던 스킬 레벨, 숙련도, 능력치 배분, 별자리와 세트 효과를 자동 계산 경로에 연결했습니다. 장비를 교체하면 장비 보너스로 바뀐 최종 스킬 레벨의 원시 수치를 다시 읽습니다. 현재 출력은 **지원되는 효과의 예상 DPS 소계**입니다. 모든 스킬의 전투 동작을 완전히 재현한 결과나 DPYes 실측값은 아닙니다.

## 1. 어디까지 바뀌었나요?

| 항목 | v3 처리 |
|---|---|
| 아이템·접사·컴포넌트·증강제 검색 | 공개 DB 레코드 선택 → 옵션 자동 반영 |
| 장비 스킬 보너스 | 전체 / 직업 / 개별 보너스 합산, 투자 여부·최종 상한 반영 |
| 스킬 포인트 | 각 레벨의 원시 배열을 사용. 세 지점 사이를 직선 보간하지 않음 |
| 숙련도·능력치 | 배분 → 파생 능력치·요구치 계산. 일부 성장식은 명시된 참고 프로필 |
| 별자리 | 별 단위 배분, 선행 별·친화도·55포인트 검사, 발동 스킬 연결·레벨 |
| 세트 | 서로 다른 조각 수에 따른 보너스 / 스킬 변경 적용 |
| 공격 | 일반 공격·기본 공격 대체·발동 공격과 지원되는 공격/약화/버프 |
| 지속 피해·조건부 발동 | 중첩·유지율·재사용 대기시간의 평균 모델. 실제 틱 재현 아님 |
| 미지원 효과 | 검증·출처 탭에서 경고. 없는 효과를 임의 피해로 대체하지 않음 |
| DPYes | 기존 JSON/CSV 로그 분석 유지. 예측 모델과 로그 집계를 별도로 표시 |

## 2. Windows 실행

1. ZIP을 **새 폴더에 전부 압축 해제**합니다. ZIP 안에서 실행하지 마세요. 기존 v2 폴더에 덮어쓰기보다 새 폴더를 권합니다.
2. `START_WINDOWS.cmd`를 실행합니다.
3. DB 준비가 완료된 뒤 브라우저에서 장비를 검색합니다. 처음에는 인터넷이 필요합니다.

런처는 Windows x64를 대상으로 작성했습니다. `.runtime` 폴더에 공식 Python 3.12.10 임베디드 배포판과 DuckDB 1.4.1을 내려받습니다. 시스템 Python을 변경하거나 관리자 권한을 요청하도록 만들지 않았습니다. PowerShell 실행 정책 설정은 해당 프로세스에만 적용합니다. 조직 PC에서 스크립트 실행을 막으면 관리자 정책을 우회하지 마세요.

이후 공개 데이터의 12개 Parquet 테이블과 별자리 데이터를 받아 `data-cache`에 정규화합니다. Parquet 파일의 SHA-256을 배포 목록과 비교하며, 아이템과 별자리 데이터 버전이 일치하지 않으면 중단합니다. 런처가 준비하는 DuckDB wheel은 고정 SHA-256을 확인합니다. Python ZIP은 공식 HTTPS 출처로 제한하지만 별도의 고정 체크섬으로 검증하지는 않습니다.

서버는 `127.0.0.1`에서만 열리며 기본 포트 8765를 사용할 수 없으면 다음 포트를 찾습니다. 사용 중 콘솔 창을 열어 두고, 종료할 때는 `Ctrl+C`를 누릅니다. 정상 시작 여부·접속 주소는 콘솔에도 표시합니다.

**Windows에서 실제로 실행해 통과한 배포본이라는 뜻은 아닙니다.** 이 환경에는 Windows와 해당 런타임이 없었고 외부 다운로드도 DNS 오류로 실패했습니다. `TEST_REPORT_KO.md`에 실행한 검사와 실행하지 못한 검사를 분리했습니다.

### 준비 후 오프라인 사용

DB가 완성된 상태에서 화면의 **DB 포함 HTML 저장**을 누르면 검색 DB와 현재 빌드를 담은 파일이 저장됩니다. 이 파일은 서버 없이 사용할 수 있도록 구현했습니다. 데이터가 큰 경우 브라우저의 메모리와 저장 제한에 영향을 받을 수 있으며, 실제 전체 DB 크기로는 아직 검사하지 못했습니다.

캐시를 사용하는 서버 모드는 다음과 같습니다.

```bat
START_WINDOWS.cmd -Offline
```

런타임이나 v3 캐시가 없으면 실패하며 자동으로 온라인 모드나 검사 표본으로 바꾸지 않습니다.

## 3. 사용하는 순서

### 장비

부위 → 본체/접두사/접미사/컴포넌트/증강제 → 검색 → 레코드 선택 → 장착 순서입니다. 한글과 영어 이름을 검색합니다. 같은 이름의 서로 다른 레벨과 부위별 접사는 구분해야 합니다.

기본 롤은 평균값이며, 수치 범위와 무기 최소·최대 피해를 구분합니다. 모든 옵션의 극단값이 동시에 나오는 실제 아이템 시드를 재현하지는 않습니다. 모든 접사 드롭 조합·승천 적법성까지 검사하지도 않습니다.

**서약운반자 DB 자동 장착**은 이름으로 실제 DB 항목을 찾습니다. 찾지 못한 장비·중복 후보는 보고하고 수치를 만들어 넣지 않습니다. 접사는 실제 부위별 레코드를 선택하세요.

### 캐릭터와 스킬

캐릭터 탭에서 레벨, 스킬·능력치 포인트 한도, 체격·교활·정신과 직업 숙련도를 배분합니다. 스킬 탭에서는 **직접 투자 포인트**만 입력합니다. 장비 포함 최종 레벨과 해당 레벨의 수치는 자동으로 바뀝니다.

서약운반자 배분 버튼은 대화에서 정한 250포인트·55별 기준안을 불러옵니다. 이는 검증된 고단 파밍 캐릭터가 아니라 배분 편의 기능입니다. 장비가 빠져 있으면 동일한 최종 레벨이 되지 않습니다.

주력 공격을 선택하고, 장판 위/저체력/피격 조건은 실제로 비교하려는 상태에 맞춥니다. 사용하는 보조 공격은 필요하면 재시전 간격을 설정할 수 있습니다. 일부 아이템 사용 스킬과 특수 동작은 자동 회전이 완전하지 않으며 진단에 표시됩니다.

### 별자리

별을 눌러 배분하고 발동 효과의 레벨과 연결할 스킬을 정합니다. 전체 DB의 별자리를 탐색하지만 모든 별자리 소환물·복잡한 발동 동작이 DPS에 포함되는 것은 아닙니다. 같은 스킬에 두 발동 효과를 연결하거나 필요한 친화도가 부족하면 경고합니다.

### 적·전투

대상의 방어 능력, 저항, 방어구 등은 장비로 결정되지 않습니다. 비교할 적을 기준으로 설정해야 합니다. 사격 유지율·산탄 명중 비율·공격 동작 시간도 전투 조건입니다. 필요하면 실측 초당 공격 횟수로 자동 추정을 보정할 수 있습니다.

**이 값들을 입력하는 것은 장비나 스킬 계수를 일일이 옮겨 적는 것과 다릅니다.** 장비·배분의 수치는 자동으로 연결하고, 적과 운영 조건만 구분한 것입니다.

### 결과

분석 탭에서 주력 공격, 발동 공격, 별도 효과, 피해 유형별 기여를 확인합니다. `A 기준 저장` 후 장비를 바꾸면 같은 조건에서 비교할 수 있습니다.

검증·출처 탭의 **미지원·누락·참고식** 경고를 먼저 읽으세요. 오류가 있는 배분이나 미지원 효과가 있는 경우, 표시된 소계를 전체 캐릭터 DPS로 해석하면 안 됩니다.

## 4. 정확도와 제한

- 장비 보너스로 변한 스킬의 중간 레벨도 원시 배열로 읽도록 구현했습니다. 정확한 배열이 없으면 임의 보간하지 않습니다.
- 원시 수치가 존재한다는 것과 실제 게임 동작까지 구현했다는 것은 다릅니다. 펫/변신 AI, 카덴스의 주기, 일부 충전·집중 스킬, 반격, 추가 폭발/파편은 완전 지원하지 않습니다.
- 전체 성장식을 확보하지 못한 항목은 표시된 참고 프로필을 사용합니다. 따라서 체력·공격/방어 능력까지 그림툴과 완전히 일치한다고 보장하지 않습니다.
- 조건부 발동과 저항 감소는 평균 유지율 모델입니다. 게임의 프레임·랜덤 시드·치명타 상관·이동·타격 지형은 재현하지 않습니다.
- DPYes는 실제 피해 이벤트를 집계합니다. 이 앱은 독립 예측 모델이며 DPYes 내부 코드나 게임 엔진의 복제품이 아닙니다.
- 그림툴 URL이나 `.gdc` 저장 파일 직접 가져오기는 없습니다. 이번 작업은 공개 DB 검색과 자동 배분 계산 경로를 확장한 것입니다.

상세 계산 범위는 `CALCULATION_SCOPE_KO.md`를 참고하세요.

## 5. 실행 검사

`TEST_REPORT_KO.md`와 `tests/reports/`에 실제 결과를 담았습니다. Windows 보고서의 `not_run`은 성공을 뜻하지 않습니다.

- 자동 계산 단위 검사: **68개 통과**
- 백엔드·로컬 HTTP 검사: **27개 통과**
- Linux Chromium UI 검사: **39개 통과**
- 기존 계산 엔진·카탈로그 회귀 검사: **48개 + 20개 통과**
- 실제 전체 DB 첫 다운로드: **검증 실패 — 개발 환경 DNS 오류**

통과한 검사는 대부분 명시적인 합성 데이터/고정 입력에 대한 구현 검사입니다. 실제 게임 피해 정확도나 모든 DB 레코드의 호환성을 입증하지 않습니다.

## 6. Windows 실제 E2E 작업

`.github/workflows/windows-e2e.yml`과 `tests/windows_e2e.py`를 포함했습니다. 실행 가능한 Windows 환경에서 **실제 CMD 런처 → 공식 런타임 다운로드 → 실제 전체 DB → Chromium → 저장 → 오프라인 재실행**을 시험하도록 작성했습니다.

이 워크플로를 포함한 것과 실행을 완료한 것은 다릅니다. 현재 첨부된 Windows 결과는 `not_run`입니다. 자세한 실행 방법은 `WINDOWS_TEST_KO.md`에 있습니다.

## 개발자 실행

```sh
python -m pip install -r requirements.txt
python build.py
python server.py --no-browser
```

오프라인 구현 검사는 Node와 Python으로 실행할 수 있습니다. 브라우저 검사는 Playwright와 Chromium이 필요합니다.

```sh
node tests/auto.test.js
node tests/engine.test.js
node tests/catalog.test.js
python tests/auto_backend_test.py
python tests/auto_ui_test.py
```

`tests/auto-catalog-fixture.json`은 **13개 아이템, 25개 스킬, 13개 별자리의 기능 검사 전용 표본**입니다. 실제 아이템 DB로 배포하거나 실제 빌드 성능으로 인용하지 마세요.
